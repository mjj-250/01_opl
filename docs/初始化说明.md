# 项目工作空间初始化说明

请完整阅读本文件，然后初始化工作空间。

## 目标目录判定

1. 获取当前 AI 会话的工作目录。
2. 获取本文件 `初始化说明.md` 的实际所在目录。
3. 将本文件所在目录自动认定为本次初始化的项目根目录。
4. 所有新目录和文件只能创建在这个项目根目录内。
5. 不要猜测上级目录、相邻目录或其他项目目录。
6. 不要要求用户点击文件夹，也不要把路径写死到本说明中。
7. 开始创建前，在回复中简短报告“目标根目录已确定为当前初始化说明所在目录”，然后直接执行。

本文件本身属于项目根目录的一部分，不需要移动。

## 二、角色和工作流程

用户在 `01-主管/草稿.md` 表达想法。主管与用户讨论，在 `01-主管/spec设计.md` 形成可验收的 spec。用户确认后，主管复制到根目录 `spec.md`。

员工阅读根目录 `spec.md`，进行一次完整评价和回访，把意见写入 `01-主管/来自员工的意见.md`。主管最多根据这次意见修改一次 spec，并重新复制到根目录。

员工按最终 spec 正式执行，在 `02-员工/当次执行记录.md` 记录实际操作、验证证据、错误和遗留事项。每个 spec 只允许一次员工回访，避免无限来回讨论。

## 三、两类经验提炼

- 员工个人经验写入前端或后端自己的执行记录和 skill，记录下次工作时应注意的技术细节。
- 项目级经验包括技巧、流程、业务规则、阶段注意事项和调研结论，统一写入 `SOP-Skills/000-候选池.md`，由主管分类并入正式 SOP 或主管 skill。

## 四、最小文件文案

### readme.md

本项目使用单轮主管—员工流程。主管与用户形成 spec，员工一次回访后执行，员工提炼经验，主管负责分配和归档。

### spec.md

```markdown
# 本轮执行方案
## 目标
## 当前状态
## 执行步骤
## 验收标准
## 允许变通范围
## 禁止范围
## 回滚方式
```

### todo.md

```markdown
# 用户任务清单
- [ ] 待用户填写
```

### 文件职责

- `01-主管/草稿.md` 保存用户原始想法。
- `01-主管/spec设计.md` 保存讨论中的方案。
- `01-主管/来自员工的意见.md` 保存员工唯一一次回访。
- `02-员工/当次执行记录.md` 保存实际操作和验证结果。
- `SOP-Skills/000-候选池.md` 保存等待主管分类的项目级经验。
