# 项目工作空间初始化说明

## 一、目录职责

```text
项目根目录
├── readme.md
├── spec.md                     # 员工正式开发规格，非设计阶段保持模板
├── todo.md                     # 当前任务清单，阶段结束归档
├── docs/
│   ├── 初始化说明.md
│   └── design/                 # 当前设计成果，按 01、02 编号
├── 01-主管/
│   ├── 草稿.md                   # 项目开头的当前原始输入，完成后归档并清空
│   ├── spec设计.md
│   ├── 设计记录.md
│   ├── 来自员工的意见.md
│   ├── specs/                  # 草稿+员工 spec 拼接归档及相关要求，三位编号
│   ├── 历史/                   # 阶段设计记录，两位编号
│   ├── 任务历史/               # 阶段 todo 与结果，两位编号
│   └── skills/agent.md
├── 02-员工/
│   ├── 当次执行记录.md
│   ├── 前端/
│   │   ├── 当前执行记录.md
│   │   ├── 历史/
│   │   └── skills/agent.md
│   └── 后端/
│       ├── 当次执行记录.md
│       ├── 历史/
│       └── skills/agent.md
├── SOP-Skills/
│   ├── 000-候选池.md
│   └── 001-….md                # 正式 SOP 使用三位编号
├── code/
├── ref/                        # 可复用参考，两位编号
├── scripts/
├── test/
└── temp/                       # 临时材料，阶段结束清空
```

新工作空间可以创建上述目录和空白模板，但不得伪造设计成果、审阅记录或员工经验。实际产生内容时才创建对应编号文件。

## 二、阶段职责

1. 设计者是掌舵者和主管，负责项目开头并管理草稿、spec、todo 和 SOP。用户确认功能和界面初版前，设计者负责边界、调研、问答、方法论、Demo、设计原型和模块审阅。
2. 原型代码仍属于设计成果，不因此提前启动员工开发。
3. 初版预期经过 1～2 轮模块审阅，以用户最终确认作为交接门槛。
4. 确认后主管写根目录员工 spec，员工一次回访，主管最多修订一次，员工正式执行。
5. 前端记录放前端，后端记录放后端；各自归档并提炼，不互相代写经验。

## 三、记录与知识分配

每一步记录执行动作、用户原文、设计结论、验证结果、正确做法、错误示例和待定项。先保存原话，再形成摘要。

阶段结束顺序：归档 → Agent 吸收 → 正式 SOP 固化 → 000 保留待验证候选 → 清理中间产物并重置模板。员工的一次 spec 完成后，必须先将当时主管草稿和根目录 spec 拼接到 specs 的同一个文件，再清空草稿和 spec；todo 仍进入任务历史。

## 四、命名

- 主管 specs 与正式 SOP：三位编号，例如 `001-`。
- 设计、任务历史、员工历史与 ref：两位编号，例如 `01-`。
- 不提前创建空审阅文件，不保留已完全吸收的重复副本。

## 五、空白模板

### spec.md

```markdown
# 本轮执行方案
## 目标
## 当前状态
## 执行步骤
## 验收标准
## 允许变通范围
## 禁止范围
## 回滚方式
```

### todo.md

```markdown
# 用户任务清单
- [ ] 待用户填写
```

当前设计与执行状态由对应 Agent、设计文档、历史记录和 `code/frontend/README.md` 说明，不写入空白模板。
