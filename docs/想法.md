# 项目愿景与长期想法

## 文件地位：只存想法，不参与日常执行

本文件用于持续保存项目的长期愿景、模块灵感和未来可能性。它不是当前设计、大任务、spec、SOP 或任何 Agent 的工作输入。

- 主管、前端、后端及员工公共工作流均不得把本文件作为日常设计、开发、审阅或验收依据。
- 日常角色无需读取本文件，也不能因为这里出现了某个想法就新增模块、修改范围或调整技术方案。
- 只有用户明确发起“大版本更换／大版本升级”时，主管才可以把本文件作为参考材料重新阅读。
- 即使进入大版本评估，这里的内容也只是候选想法，仍需重新经过边界确认、设计审阅和用户审批。
- 当前有效产品范围仍以 `docs/design/`、根目录 `todo.md`、根目录 `spec.md` 及用户明确审批为准。

## 一、项目长期愿景

希望逐步形成一个真正服务于个人生活的系统：不仅安排任务，也帮助管理阶段目标、日常记录、知识与经验、财务流水和资产，以及个人信息。

系统不是简单的待办清单，而是让每个生活模块都能按照自己的目标、方法论和规划生成任务，再通过今天、四象限、日历和复盘形成执行闭环。最终希望减少盲目忙碌，让有限时间投入到真正想完成的事情上。

更远的愿景是：各模块在积累足够内容后，可以逐步升级为自己的 Agent 或知识库，再由一个主 Agent 统筹规划。自动化可以帮助减少重复操作，但不能代替用户决定人生目标和验收真实成果。

## 二、已经提出过的模块与能力

以下是用户曾经提出的模块和想法汇总，仅用于长期记忆，不代表它们都已进入当前版本。

### 001 日常生活

- 上班族作息、吃药、泡茶等生活基调事项。
- 为容易拖延的事情设置具体、低阻力的“启动动作”。
- 每周家庭卫生、拖地等周期事项。
- 每月剪头发等个人事务。
- 记录亲友生日和重要日期。
- 保存方法论、正确做法、错误记录等生活经验。

### 002 健身与健康

- 在家训练，器械以少量哑铃等现实条件为基础。
- 不盲目打卡，以实际效果作为阶段目标。
- 曾设想的观察方向包括：一个月关注气色等变化，三个月关注体型和力量等变化。
- 目标、训练规划、执行记录和真实效果需要相互关联。
- 83 天习惯养成只是曾经讨论过的可选模板，不是固定科学结论。

### 003 学习

- 学习模块内部可以拥有可增删改的子模块。
- AI 绘画：已有课程，可以围绕课程、练习和总结组织学习。
- Agent 开发：通过实际案例、项目或技术总结形成能力。
- 证书学习：以证书到手等可观察结果作为完成标准。
- 不同学习方向可以有不同的完成标准，例如完成三个案例、学完视频并总结、获得证书。

### 004 开发与技术磨练

- 本职程序员需要保持开发手感，持续学习新的开发技巧。
- 将经验沉淀为可复用的代码、文档、工具、方法论或知识库。
- 尝试让沉淀内容创造价值，例如制作自己的快速开发工具。
- 通过程序丰富或简化生活，例如在安全、合规和可控的前提下减少重复操作。
- 技术学习不只为了“学过”，还应通过案例、作品和真实问题检验能力。

### 005 游戏

- 对内容较多、需要重复完成的事项进行任务整理。
- 远期可以探索程序或 Agent 辅助完成适合自动化的部分。
- 游戏不仅有日常任务，也有长期成就目标。
- 曾提出的例子：王者荣耀希望各路都会，每一路寻找攻略并熟悉三个英雄。
- 攻略存在版本时效性，需要关注更新、熟练度和实际掌握情况。

### 006 财务

- 记录每日消费、账户流水和总资产。
- 账户初始数据可以简单起步，允许后续逐步校正。
- 花呗、美团月付等信用平台既可能是支付方式，也可能形成还款事项。
- 需要避免信用消费与还款重复计算支出。
- 还贷平台和还贷记录也是长期财务管理的一部分。

### 007 个人信息与账密

- 系统远期可以具有用户登录和个人信息边界。
- 曾提出账密记录模块的需求。
- 真实密码的保存方式、安全边界和是否实现，需要在对应版本单独确认，不能从愿景直接推导实现。

### 008 文档、知识与经验

- 统一管理方法论、攻略、学习总结、正确做法和错误记录。
- 文档可以关联模块、目标、任务或成果。
- 内容不仅用于保存，还应在后续行动、复盘和模块成长中重新发挥作用。
- 远期可能成为各模块知识库和 Agent 的基础。

### 009 任务、目标与执行系统

- 四象限用于组织任务的重要与紧急程度。
- 模块根据自身规划和阶段目标生成任务。
- 一个时期内聚焦少数真正重要的成就目标，避免有限时间被过多并行目标稀释。
- 今天、日历、每日记录、早晚计划和晚间复盘共同支持执行。
- 任务完成不必然等于目标达成，真实成果需要单独验收。

## 三、岗位追求与职业发展

### 当前理念

职业发展不只是一组学习任务，也不只是“把技术练熟”。它同时包含长期方向、技术能力、岗位市场和个人成果之间的持续校准。

- **学习**：获得知识并形成理解。
- **技术磨练**：通过案例、项目、问题和作品把知识变成实际能力。
- **岗位调研**：了解目标岗位、行业变化、能力要求和市场需求，用来校准学习与磨练方向。
- **岗位追求**：把上述内容组织成较长期的职业发展目标，而不是零散地跟随热点学习。

### 岗位调研是否属于技术磨练

岗位调研与技术磨练有关，但两者不完全等同：

- 技术磨练回答“我怎样把能力真正练出来”。
- 岗位调研回答“市场需要哪些能力，我准备走向哪里”。
- 岗位追求或职业发展可以作为更上位的方向，把学习、技术磨练和岗位调研联系起来。

因此，岗位调研可以影响技术磨练的方向，但不应被缩减成技术练习本身。

### 未来可能包含的内容

- 未来希望发展的岗位方向和长期职业目标。
- 目标岗位、行业与招聘要求调研。
- 当前能力与目标岗位之间的差距。
- 学习方向、技术主题和实践项目。
- 可展示的案例、作品、经验总结及其他能力证据。
- 定期复盘方向是否仍然符合个人追求和外部变化。

### 模块归属想法（未决定）

在当前概念中，它既可以暂时被理解为“开发／技术磨练”的一个职业发展方向，也可能在未来成为独立的“职业发展／岗位追求”模块。

如果内容只围绕程序员的技能与岗位，它可以与开发模块紧密关联；如果未来还包括更广泛的职业选择、行业转换、岗位机会和长期人生规划，独立模块可能更清楚。

这里不做归属决定，也不修改当前模块设计，留给未来大版本讨论。

## 四、模块自治与远期 Agent 愿景

- 每个模块可以有自己的目标、规划、任务、记录、文档和方法论。
- 模块之间保持高内聚、低耦合，避免所有功能堆在一个通用任务系统里。
- 四象限、日历等系统能力负责呈现和协同，不替代各模块自己的规则。
- 模块成熟后可以逐步发展为知识库或专属 Agent。
- 主 Agent 的远期职责是理解整体目标、协调有限时间和提供规划建议，而不是无边界地自动控制生活。
