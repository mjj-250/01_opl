### 已确认的目标

### 设计推进顺序

1. 先明确个人系统的用户目标、使用场景和内容边界。
2. 调研 3 个同行 Web 产品，记录首页结构、任务组织、目标与周期、记录方式、模块扩展和隐私处理等界面参考。
3. 根据调研结果形成模块清单和模块间关系。
4. 为每个模块编写详细调查问卷，确认输入、输出、周期、完成标准、记录方式和后续扩展方向。
5. 汇总用户确认结果，再形成可验收的产品设计方案。

### SOP 与 Skill 的处理决定

- 本轮先采用上面的产品调研与设计确认顺序，不把通用开发流程 SOP 作为前置条件。
- 产品流程中的可复用做法，先在本记录中验证。完成一轮后再把稳定、可复用的经验写入 `SOP-Skills/000-候选池.md`。
- 开发流程、技术栈、数据存储、账号密码保护和 Agent 协作方式，等产品设计确认后再单独整理对应 SOP 或 Skill。
