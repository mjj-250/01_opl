# 本轮执行方案

## 目标

1. 巩固已通过交互式问答确认的产品设计基线，并同步到设计记录、三份问卷和模块科学方法论 SOP。
2. 在 `ref/ui-style-demos/` 制作三种视觉风格的“今天”四象限可点击 Demo：清爽效率风、温暖生活风、深色控制台风。
3. 三种 Demo 使用相同数据和交互；根据用户最新决定，三种主题全部保留并提供全局切换，默认使用温暖生活风。
4. 本轮直接在 `code/frontend/` 建立 React + TypeScript + Vite 完整前端原型，并提供目录结构说明。

## 当前状态

- 产品默认入口为“今天”，首屏展示完整经典四象限，所有待办与今日任务同屏显示，今日任务带明确标记。
- 任务由模块及其规划生成，也支持临时新增；四象限按任务属性自动归类，手动移动后锁定，可恢复自动归类。
- 首版不引入 AI，不接后端；完整原型将覆盖任务、模块、目标、日历、记录、文档、财务和账密占位。
- 用户已决定保留全部三种主题，默认温暖生活风；完整 React + TypeScript 前端、目录说明、单元测试、生产构建和浏览器验收均已完成，当前等待用户使用反馈。

## 执行步骤

1. 先将问题、当时选项和用户原话保存到 `docs/04-初版详细设计问答原稿.md`，再将确认结果写入主管设计记录及三份设计问卷，以最新选择覆盖早期候选规则。
2. 新建 `SOP-Skills/002-模块科学方法论.md`，记录低阻力启动动作、83 天可选习惯模板和模块自治原则。
3. 建立风格选择入口及三个本地 Demo，共用任务数据与交互逻辑，通过不同主题呈现相同样例。
4. Demo 支持临时新增、四象限拖动、手动锁定提示和解锁恢复自动归类。
5. 检查三个页面的浏览器运行、交互一致性、桌面与窄屏布局以及控制台错误。
6. 使用 React、TypeScript、Vite 建立模块化前端，复用 dnd-kit、FullCalendar 和图标组件。
7. 完成今天、模块、目标、日历、每日记录、文档、财务、账密占位页面，以及全局三主题切换。
8. 补充目录说明、业务规则单元测试、构建和浏览器交互检查。

## 验收标准

- 三个 Demo 可直接打开，无需安装依赖或启动服务，且包含统一的风格选择入口。
- 三个 Demo 的初始任务、字段和交互结果一致，仅视觉风格不同。
- 任务卡片显示名称、模块、启动动作、计划或截止时间，以及今日、锁定等状态。
- 可新增临时任务并进入正确象限；拖动后保持锁定，解锁后恢复自动归类。
- 桌面和窄屏下无关键文字溢出，主要操作可用，浏览器控制台无错误。
- 原始问答、结构化结论和设计记录相互关联；摘要不得替代用户原话，未直接回答的问题不得写成已确认。
- 设计记录、问卷状态与根目录本方案一致。
- 完整前端默认展示温暖生活风，可即时切换清爽效率风和深色控制台风，刷新后保留主题选择。
- 完整前端目录按页面、业务组件、共享组件、状态、类型、数据和工具分层，业务规则可独立测试。
- 项目可安装依赖、通过单元测试与生产构建，并在本地浏览器完成主要页面和交互验收。

## 允许变通范围

- Demo 可使用原生 HTML、CSS 和 JavaScript，完整原型仍采用 React + TypeScript。
- 可在不增加业务差异的前提下补充响应式布局、键盘操作和风格切换入口。
- 视觉细节可在三种主题内自行调整，但不得改变共同的样例内容与业务行为。

## 禁止范围

- 不在本轮接入后端、数据库、真实账号密码或外部平台同步。
- 不使用 AI 自动判断任务属性，不实现 Agent、自动打卡或外部程序回写。
- 不把完整原型接入后端或真实数据，不提前实现账密存储；三种主题不得相互删除。
- 不覆盖用户已有的未提交改动，不提交或推送 Git。

## 回滚方式

- 新增内容集中在 `ref/ui-style-demos/`、`code/frontend/` 和 `SOP-Skills/002-模块科学方法论.md`，可分别移除。
- 文档修改仅追加或替换本轮模板及问卷记录；如需回滚，按 Git 差异恢复对应文件，同时保留用户原有改动。
