# 大任务发起、审批与 Spec 拆分流程

## 文件目的

把“按开发流程阶段规划下一步”变成可复用的主管动作：先提供审阅参考，再在根目录 `todo.md` 建立带候选 spec 简述的当次大任务，等待用户在草稿中审批；审批前不改正式 spec。

## 001 概念与边界

- **开发流程阶段**：产品设计、模块审阅、正式开发、验收等阶段，回答“项目走到哪一步”。
- **大任务**：一个阶段内可独立验收的目标。一个阶段可以连续有多个大任务，一个大任务也可以跨多次执行。
- **Spec**：大任务下的一次具体执行单位，需要有明确范围、产出和验收条件。大任务可以只包含一个 spec，不为了形式强拆。
- **候选 spec 简述**：写在根目录 `todo.md` 中的规划，不代表已批准，也不等于已经写入根目录 `spec.md`。
- **审批入口**：`01-主管/草稿.md`。用户在这里保留原始审批意见，主管不得用摘要替代原文。
- **员工交接入口**：根目录 `todo.md` 与 `spec.md`。员工先读大任务，再读当前具体执行规格。

## 002 标准动作

### 第一步：判断阶段并生成临时参考清单

主管先依据当前设计文档、任务历史和产品状态判断所处阶段，不直接跳到员工开发。

在大任务规划时，于 `temp/` 创建与大任务同编号的参考清单，例如：

`temp/001-初版模块审阅参考清单.md`

参考清单用于帮助用户检查和审批，可包含审阅维度、页面或模块检查点、参考材料入口。它只提供提示，不替用户作结论，也不是必须逐项填满的问卷。任务结束并提炼后清理。

### 第二步：在根目录 todo 建立当次大任务

根目录 `todo.md` 就是当次大任务文件，标题使用三位大任务编号，例如：

```markdown
# 大任务 001：初版模块审阅与设计定稿
```

主管没有 `01-主管/任务/` 目录。`todo.md` 至少记录：

1. 所属阶段、任务状态和提出背景。
2. 用户原始要求。
3. 目标、非目标、输入与参考材料。
4. 预期交付物和大任务总体验收标准。
5. 候选 spec 的编号、名称、目的、简述、产出和启用条件。
6. 当前审批范围与下一步。

当前任务只放在根目录 `todo.md`，不放进 `任务历史/`。完成后，任务原文及结果按既有两位编号规则进入 `01-主管/任务历史/`，保留原大任务编号以便追踪，然后将根目录 `todo.md` 恢复为空白模板。

### 第三步：等待用户在草稿中审批

主管建立 todo 和参考清单后停下，不自行批准。

用户在 `01-主管/草稿.md` 中写审批、修改或否决意见。主管下一步先读取原话，再区分：

- 仅批准大任务方向。
- 批准某个或某些候选 spec。
- 要求调整任务目标、范围或 spec 拆分。
- 明确确认设计定稿或允许交接员工。

批准大任务不自动等于批准所有候选 spec；未明确授权的执行项继续保持候选状态。

### 第四步：按批准范围执行

- 只执行用户已批准的范围内工作，新增范围重新记录并等待确认。
- 需要形成正式执行规格时，才把批准内容写入根目录 `spec.md`；未获批准前不得修改。
- `todo.md` 与 `spec.md` 都对员工可见：前者说明为什么做及整体目标，后者说明这一次具体做什么和如何验收。
- 根目录 `spec.md` 仍是员工正式开发规格。设计审阅任务不得借“大任务已批准”提前交接员工。
- 可选 spec 只有满足启用条件并得到批准后才执行；无必要时标记不启用并记录原因。

## 003 状态与验收

大任务建议使用：`待审批` → `已批准/执行中` → `待验收` → `已完成`。被否决或取消时保留原决定与原因，不删除历史。

大任务验收看阶段目标是否由用户确认，不以“候选 spec 都执行过”或“代码写完”代替。单个 spec 的完成也不能自动代表整个大任务完成。

## 004 正确做法与错误示例

### 正确做法

- 先给 `temp/001-…参考清单.md`，再把大任务 001 和候选 spec 简述写入根目录 `todo.md`，状态标为“待审批”。
- 用户把“同意任务，但先做第一个 spec”写入草稿后，只启动第一个 spec。
- 员工交接时同时提供根目录 todo 和 spec，使员工理解整体目标与当次边界。
- 第二个审阅轮次没有必要时，说明不启用的原因，以大任务验收标准为准。

### 错误示例

- 在主管目录另建 `任务/`，造成当前大任务与根目录 todo 两个来源。
- 用户刚询问“下一个大任务是什么”，主管就直接改根目录 spec 或开始开发。
- 把 todo 里的候选 spec 简述当成已经批准的执行命令。
- 把当前待审批任务放进任务历史，造成已经完成的错觉。
- 用助手摘要覆盖草稿中的用户审批原文。
- 为了凑齐预设 spec，强行增加第二轮审阅。
