# 个人系统产品设计与开发流程

## 文件状态

当前为本项目使用的流程草案。完成一轮后，将稳定、可复用的做法提炼到 `000-候选池.md`，再由主管决定是否形成正式 SOP 或 Skill。

## 一、产品设计阶段

### 1. 定下内容边界

- 根据用户原始想法明确系统要解决的问题、主要用户场景和第一版模块范围。
- 通过调查问卷确认任务、目标、记录、文档和隐私内容。
- 产出产品边界问卷和初步内容设计。

### 2. 调研同行产品

- 选择与核心目标直接相关的同行产品。
- 重点观察任务入口、四象限、今天页面、优先级、周期任务、目标和完成反馈。
- 将图片或截图放入 `temp/`，保留来源和产品名称。
- 不因为同行存在某个功能就自动纳入本项目。

### 3. 详细设计

- 根据用户对调研结果的取舍，形成模块、任务、目标和记录的详细内容设计。
- 通过问卷确认字段、状态、关系、默认入口、页面重点和暂缓范围。
- 将用户回答记录到 `01-主管/设计记录.md`，再形成可验收的设计方案。

### 4. 第一版纯界面

- 先制作内容齐全的纯界面版本。
- 默认入口是“今天”单日页面。
- 界面需要覆盖任务四象限、模块、阶段目标、日常记录、消费记录和账号密码记录的已确认内容。
- 这一阶段不要求前后端功能可用。

### 5. 用户进行大方向调整

- 用户检查模块划分、页面入口和信息层级是否正确。
- 主管记录调整意见，设计者修改界面结构。
- 大方向确认后再进入页面功能细节调整。

### 6. 用户进行功能细节调整

- 用户逐页检查任务创建、四象限移动、周期任务、阶段目标、记录和查询等操作。
- 设计者根据反馈继续修改界面。
- 直到初版设计内容和主要操作都得到确认。

## 二、开发准备和开发阶段

### 7. 定下初版后再进入开发

- 用户确认初版界面和内容后，才进入前后端开发。
- 进入开发前再判断是否需要下载或启用开发相关 Skill。
- 前端和后端分别放在 `code/` 下的独立项目文件夹。
- 前端使用 Node 环境，后端使用 Python 环境，各自管理依赖。
- 后端首版使用 SQLite，初期可以没有正式数据库文件，由项目运行时初始化。
- 先完成用户指定的核心任务流程，再处理低优先级小功能。

### 8. 开发中的使用体验反馈

- 用户实际使用已完成的功能。
- 用户集中提出一轮使用体验意见。
- 设计者和开发者根据反馈调整交互、字段和页面。

### 9. 确认可用后进入正式开发阶段

- 用户确认各个核心功能大致正常可用。
- 通过版本控制工具上传代码。
- 后续新增功能按正式开发流程管理。

## 三、记录要求

- `01-主管/设计记录.md` 记录每一轮做了什么、用户确认了什么以及设计变更。
- 设计记录需要同时记录正确的标准做法、错误示例和待解决问题。
- `02-员工/当次执行记录.md` 记录实际执行、验证证据、错误和遗留事项。
- 项目级经验先写入 `SOP-Skills/000-候选池.md`，由主管分类后再合并进正式文件。
