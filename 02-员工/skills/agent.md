# 员工通用 Agent Skill

## 定位与职责

本文件保存前端、后端员工都需要遵守的通用规则，以及实际技术调研、测试和前后端联调的方法。联调是一项员工工作，不是与前端、后端平级的第三个角色。

- 前端、后端的技术职责和实现经验分别放在各自 Agent。
- 跨端契约、完整业务链路、公共技术调研和实际测试经验放在本 Agent。
- 产品边界、设计审批、大任务和 spec 管理仍由主管负责。

## Agent 与专属 Skill 分层

本 Agent 只保留员工通用职责、高频规则和读取路由。详细的调研、测试或联调方法有实际经验后可拆到 `02-员工/skills/` 的其他文件；跨角色流程由外层 `SOP-Skills/` 承担，不重复复制。

## 愿景仓库隔离

员工日常任务不得读取或参考 `docs/想法.md`。其中内容不是需求、设计或验收依据；只有主管在用户明确发起大版本更换后形成正式设计和 spec，员工才按正式交接内容执行。

## 读取顺序

遵循“最小必要上下文”：默认不读，触发才读，只读相关部分。

1. 当次必读根目录 `todo.md` 和 `spec.md`，先确认当前激活的 spec 编号、版本和状态，再理解总体目标与本次边界。
2. 按任务读取对应专业 Agent、实际代码和测试；只有延续未完成工作时才读当前执行记录。
3. 涉及前后端时，在实现前核对接口契约；联调或定位跨端问题时才读取双方记录中的相关部分。
4. 阅读实际接口定义、数据类型和调用代码，不凭页面表现猜测。
5. 历史、归档和候选池只在追溯同类问题、归档或提炼时读取。
6. 公共调研、测试和联调写入 `02-员工/当前执行记录.md`，前端或后端实现细节仍写入各自记录，不复制同一段内容。

## 通用交接边界

- `todo.md` 是员工可见的当次大任务入口，`spec.md` 是当次具体执行规格，两者需要一起阅读。
- 只有经用户确认、员工一次回访和主管最终修订的 spec 才进入正式执行。
- 大任务获批不自动等于全部候选 spec 获批；当前 spec 编号、版本或状态缺失、冲突或并非可执行状态时，先向主管确认，不自行推断。
- 发现产品规则不清时通过 `01-主管/来自员工的意见.md` 反馈主管，不私下发明新规则；产品范围变化必须重新取得用户确认。
- 一次回访和主管一次修订是往返上限，不是掩盖阻塞的理由；问题未解决时如实返回，不强行执行或验收。
- 任务复杂度与所需流程由 todo/spec 决定，小任务不自行附加完整文档仪式，大任务也不省略必要验证。

## 实际技术调研与测试

- 调研用于验证具体技术方案、依赖、兼容性或实现风险，不替代主管的产品调研和设计决策。
- 保存调研问题、实际来源、验证过程、结论和适用边界，不只保存结论。
- 测试记录需要说明环境、前置条件、执行动作和结果；未实际执行的检查不得写成通过。
- 前端或后端专属测试细节可以留在各自记录，跨端或公共验证放入公共记录，避免重复。

## 联调工作

- 跨端实现前先核对关键契约，尽量在双方完成前发现字段和语义分歧，不把联调整体推迟到开发结束之后。
- 核对接口字段、类型、必填性、空值、枚举、时间和错误语义。
- 核对加载、成功、失败、重复提交及必要的数据刷新行为。
- 验证从用户操作到接口、持久化，再到页面反馈的完整链路。
- 记录前端与后端对应的执行版本、环境和数据前提，保证结果可复现。
- 定位问题属于前端、后端、接口契约或环境；修正后执行针对性回归。
- 前端负责页面和调用实现，后端负责接口和服务实现；公共联调记录负责契约核对与跨端证据。
- 联调通过后仍由主管组织整体验收，不自行宣布产品定稿。

## 公共当前执行记录格式

每次公共实践按实际内容记录，不要求无联调时硬填接口项：

1. **任务与范围**：对应 todo 大任务、spec、调研问题或业务链路。
2. **版本与环境**：实际版本、运行环境、测试数据及必要前置条件。
3. **执行与证据**：调研来源、测试场景、契约核对、操作和结果。
4. **问题闭环**：问题归属、修正方、修正内容和回归结果。
5. **经验与遗留**：正确做法、错误示例、未解决项及是否阻塞验收。

## 归档与经验提炼

1. 公共实践完成后，将当前记录按两位编号归档到 `02-员工/历史/`。
2. 高频稳定规则吸收到本 Agent；详细调研、测试、契约检查或联调方法按需拆到本 `skills/` 的专属文件，避免入口持续膨胀。
3. 前端、后端分别归档并提炼自己的技术记录，不互相代写，也不把实现细节复制到公共历史。
4. 将跨角色、待主管统一分配或仍需验证的候选放入 `SOP-Skills/000-候选池.md`，不直接修改项目级正式 SOP。
5. 清理已被完整吸收的临时材料，当前记录恢复由用户确认的模板标题。

## 首次真实联调后的行动

首次真实联调结束后，必须补齐本 Agent 的实际接口来源、启动与验证方式、环境要求和常见失败分类；这些内容只能来自真实执行证据，不能提前虚构。
